S7-1 设备框架

一张设备表 + 四个统一接口

内核维护 device_t 表：每个设备一行（名字/主设备号/中断号/能力）。上层找设备用 device_get(major)，分发中断用 device_by_irq(irq)。
  • 统一接口：read / write / ioctl / irq
  • device_register 注册、DEV_MAX=8 槽
  • 主设备号唯一（类似 Linux major）
实测通过 · 注册表打印正确
S7-2 三大设备驱动化

键盘 / 定时器 / 串口

三个设备各自暴露 keyboard_device() / timer_device() / serial_device()，把自己挂进设备表。
  • kbd major=1 · IRQ1 · read（读一键）
  • timer major=2 · IRQ0 · ioctl（查 ticks/uptime）
  • com1 major=3 · IRQ4 · write（串口输出）
实测通过 · 三设备齐全
S7-3 中断按设备分发

irq_handler 查表分发

中断进来不再 if/else 判断，而是 device_by_irq(irq)->irq() 直接调对应驱动；内核只保留"策略层"（调度/状态栏）。
  • IRQ0 → timer_tick（设备层）+ 调度策略（内核层）
  • IRQ1 → keyboard_handle_irq
  • 将来加新设备 = 注册一行，不改中断代码
实测通过 · 0 页错误

设计修正（2 处内核 Bug + 1 处环境配置）

BUG-S7-01：serial_printf 不支持 %- 左对齐 → 设备表打印错乱

串口格式化只跳宽度数字、不跳 -，%-6s 被拆成字面字符 + 参数错位（major 变成指针值）。修正：格式化时跳过 '-' 标记。

BUG-S7-02：serial_printf 不支持 %c → 读键显示假象 'c'

键盘设备接口明明读到 'z'，串口却打印 'c'——因为 %c 无分支，格式串里的 'c' 被原样输出。修正：serial_printf 增加 %c 分支。实测后正确显示 'z'。

环境修复：Bochs clock sync=none → 虚拟时钟加速约 326 倍

sync=none 下 Bochs 虚拟时钟按模拟速度全速跑：PIT 实测 ~32.6kHz（应为 100Hz），uptime 显示"1 小时"而真实只过了几分钟。修正：bochsrc 改 clock: sync=realtime，PIT 恢复真实 100Hz（串口核验 29s/2910 ticks）。
