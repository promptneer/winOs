第九阶段：信号与同步（sleep / 信号量 / 互斥锁）

一句话意义：程序不再"抢着干活"，而是学会排队和睡觉——sleep 让进程主动睡一会儿、醒来自动继续；信号量/互斥锁 让多个进程抢同一个资源时一个进、另一个等，绝不同时挤进去。全部 Bochs 实机 + 串口 + 截图验证通过，互斥违规 = 0。

三大件：是什么、怎么用

大白话对照 —— 系统从"只会轮流跑"变成"会睡觉、会排队"。
S9-1 信号量

semaphore：通行证

信号量像一个"通行证盒子"：盒子有 value 张通行证。P（sem_wait） 拿走一张（没有就排队等）；V（sem_signal） 放回一张并叫醒排队的人。FIFO 先来先等。
  • sem_create(value)、sem_wait(id)、sem_signal(id)
  • syscall 18/19/20
  • 排队者内核状态显示 SLEEPING
实测通过 · block/唤醒闭环
S9-2 互斥锁

mutex：一把钥匙

互斥锁 = 只有 1 张通行证 的信号量（二值信号量）。谁拿到谁进"小黑屋"（临界区），别人只能在外面等；出来才交钥匙。
  • mutex_create()、mutex_lock(id)、mutex_unlock(id)
  • syscall 21/22/23
  • 同一时刻只有一个进程在临界区
实测通过 · 16 次进出零违规
S9-3 sleep 睡眠

sleep：睡醒再干活

进程调用 sleep(ticks) 后主动让出 CPU 睡指定时长（1 tick=0.01s），到点自动醒来继续。睡眠期间不参与调度——把 CPU 让给别人。
  • syscall 17 sleep(ticks)
  • 内核每 tick 唤醒到期进程
  • ps 显示睡眠进程状态为 sleep
实测通过 · 准时醒 + 期间让出

串口铁证（COM1）

Bochs 2.8 实机，全程 0 页错误、16 次进出零互斥违规。同一把锁，C1/C2 交替进出。
sleep：C1 睡 60 ticks，期间 C2 独占PAGE_FAULT = 0
[sync] demo proc pid 1
[sem] create sem0 value=1            # 互斥锁 = 初值 1 的信号量
[sched] pid2 sleep 60 (tick=1704 wake=1764)   # C1 睡觉 60 ticks
[pid3] C2 IN                         # C2 拿到锁，连进 3 轮
[pid3] C2 OUT
[sched] pid2 wake (tick=1764)        # 60 ticks 后 C1 准时醒来
[pid2] C1 slept                      # 睡醒报告
[sem] wait sem0 pid2 block (q=1)     # C1 想进临界区，但 C2 占着 → 排队！
[sem] signal sem0 pid3 handoff wake pid2  # C2 释放 → 直接把锁交给 C1
[pid2] C1 IN ... [pid2] C1 OUT

[pid3] C2 OUT       # C2 出（中间 sleep 20 ticks 占用）
[pid2] C1 IN        # C1 进（只有 C2 交出锁之后）
[pid2] C1 OUT
[pid3] C2 IN ...    # 严格交替，绝无 "IN 后紧跟另一个 IN"

设计修正（重要）

修正：信号量 V 操作的"唤醒竞态"——先增 v 再唤醒，第三方可抢先拿走通行证

第一版 sem_signal 先 value++ 再唤醒等待者：C2 释放后 C1 被唤醒，但 C2 下一轮 wait 抢先把 v 拿走，C1 醒来误以为拿到锁 → 两个进程同时进临界区（实测抓到 1 次违规）。修复：有等待者时 V 不增 v、直接把锁"交接"给队首进程（handoff），防止抢占。修复后 16 次进出零违规。
