B · S4-1 独立地址空间

核心判据：3 个进程各自独立的页目录（pd 各不相同），调度切换时 CR3 跟着换，全程 0 页错误。

T-03run：启动 3 个用户进程，各占独立地址空间
run
VGA 屏幕（应显示）
created user procs: pid 1 2 3
scheduler started: 3 procs round-robin (0.1s quantum)
串口 COM1（应出现）
[dbg] addrspace pd=124000 pt1=125000 code 400000->122000 stack 701000->123000
[dbg] addrspace pd=129000 pt1=12a000 code 500000->127000 stack 711000->128000
[dbg] addrspace pd=12e000 pt1=12f000 code 600000->12c000 stack 721000->12d000
[sched] pid1 -> pid2 (pd=129000 esp0=...)
[sched] pid2 -> pid3 (pd=12e000 esp0=...)
[sched] pid3 -> pid0 (pd=110000 esp0=0)
[sched] pid0 -> pid1 (pd=124000 esp0=...)
# 大量行：[pid1] user1: 000000 / [pid2] user2: ... / [pid3] user3: ... 计数递增
判据① 3 行 addrspace 的 pd 各不同（124000/129000/12e000）；② sched 行 pd 随进程切换变化（回 shell 是 110000）；③ 串口全文 PAGE_FAULT = 0；④ user1/2/3 计数递增。
T-04ps（run 运行中）：进程表 4 行
ps
VGA 屏幕（应显示）
PID  STATE   NAME       TICKS  CODE
  0  run     shell      N  0
  1  ready   user1      N  400000
  2  ready   user2      N  500000
  3  ready   user3      N  600000
串口（无新增输出）
# ps 只刷屏
判据4 行进程，NAME 是 shell/user1/user2/user3，CODE 列 = 0/400000/500000/600000，TICKS 是递增数字（不用固定值）。

C · S4-2 fork 分身

先 stop 清场再 fork。核心判据：pid1 调用 fork() 后内核造出 pid2，父子各自独立计数。

T-05stop 清场（每次换演示前先执行）
stop
VGA 屏幕（应显示）
scheduler stopped, all user procs terminated
串口 COM1（应出现）
[stop] scheduler stopped
判据回显上述两行。之后 ps 只显示 shell 一行。
T-06fork：user4 分身出子进程，父子同时跑
fork
VGA 屏幕（应显示）
created fork-demo proc: pid 1
scheduler started: fork demo (0.1s quantum)
串口 COM1（应出现）
[fork] demo proc pid 1
[fork] pid 1 -> child pid 2 (pd=129000 esp0=...)
# 之后交替出现（父打印 parent、子打印 child，各自独立计数）：
[pid1] fork: parent 000000
[pid2] fork: child  000000
[pid2] fork: child  000001
[pid1] fork: parent 000001
# ...计数递增，一直交替
判据① 串口出现 [fork] pid 1 -> child pid 2；② [pid1] 与 [pid2] 同时打印、计数各自独立（互不干扰）；③ PAGE_FAULT = 0。

ps
VGA 屏幕（应显示）
PID  STATE   NAME       TICKS  CODE
  0  run     shell      N  0
  1  ready   fuser4     N  610000

串口（无新增输出）
# ps 只刷屏
判据pid 1 和 pid 2 都存在（父进程名被标成 fuser4 = fork 的 user4），CODE 都是 610000 —— 父子共用同一份程序、各自独立内存。

D · S4-3 exec 变身

核心判据：同一个 pid，先打印 user5 的声明，exec 后变成 user2 程序继续跑（pid 不变、pd 不变）。

T-08exec：user5 变身成 user2
stop（先清场）exec
VGA 屏幕（应显示）
created exec-demo proc: pid 1
scheduler started: exec demo (0.1s quantum)
串口 COM1（应出现）
[exec] demo proc pid 1
# 变身前（还是 user5 程序）：
[pid1] user5: before exec...
# 内核执行 exec(1)：
[exec] pid1 -> program user2 (entry=500000 pd=124000)
# 变身后（还是 pid1，但跑的是 user2 的代码）：
[pid1] user2: 000000
[pid1] user2: 000010
[pid1] user2: 000020
# ...user2 计数递增
判据① 变身前出现 user5 声明行；② 出现 [exec] pid1 -> program user2，且 pd=124000 与变身前一致（进程没换地址空间）；③ 之后输出全是 [pid1] user2:（同一个 pid！）；④ PAGE_FAULT = 0。
T-09ps（exec 后）：进程名字已变成 user2
ps
VGA 屏幕（应显示）
PID  STATE   NAME       TICKS  CODE
  0  run     shell      N  0
  1  ready   user2      N  500000
串口（无新增输出）
# ps 只刷屏
判据NAME 从 fuser4/user5 变成 user2、CODE 变成 500000 —— 进程变身已反映到进程表。

E · S4-4 用户态文件系统

核心判据：user6 通过系统调用创建 hello.txt、写入、读回、打印，数据存内核内存盘。

T-10fs：文件系统演示（创建/写/读 hello.txt）
stop（先清场）fs
VGA 屏幕（应显示）
created fs-demo proc: pid 1
scheduler started: fs demo (0.1s quantum)
串口 COM1（应出现）
[fs] demo proc pid 1
[fs] open created 'hello.txt' fd=0        # 首次创建
[fs] open 'hello.txt' fd=0 (exist)        # 之后每轮：文件已存在
# 写入 16 字节 -> 关闭 -> 重开读取 -> 串口打印读回内容：
[pid1] Hello WinPP FS!
[pid1] Hello WinPP FS!
[pid1] Hello WinPP FS!
# ...循环持续
判据① 首轮出现 open created 'hello.txt' fd=0；② 之后反复出现 (exist)（文件被保留在内存盘）；③ [pid1] 循环打印 Hello WinPP FS!（写入-读回闭环）；④ PAGE_FAULT = 0。
T-11fslist：文件表里有 hello.txt
fslist
VGA 屏幕（应显示）
NAME            SIZE   FD
hello.txt         16  0
串口 COM1（应出现）
[fs] list: 1 files
判据文件表 1 行：hello.txt，SIZE=16（写入 16 字节），FD=0。SIZE 若不是 16 说明写/读有问题。
