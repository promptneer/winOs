Bug 归因全记录（三根钉子全拔）

err=5 → err=6/7 → 0 错误
钉子现象根因修复
#1PAGE FAULT @0x400000 err=5（P 存在 / U 无用户位）map_page 只给 PTE 写 USER 位，PDE 仍是无 U 的恒等映射项 → 用户态访问 4MB+ 先查 PDE 即拒绝map_page：flags 含 U 时给 PDE 补 0x4，实测 pd=112067 生效
#2修 #1 后 fault @0 err=6/7（用户"程序"执行垃圾）zig cc 的 lld 不支持 .incbin：.userprogs 段字节未进 kernel.bin，_userN_start 符号指向的地址实为页表垃圾（src=0x110000 = PD 页）弃 .incbin，build 时用 Python 把 userN.bin 转成 C 数组 users_inc.c/.h 内嵌，kernel.bin 检出 user1 机器码特征 ✓
#3（连带隐患）_kernel_end 在 .userprogs 之前pmm 以 _kernel_end 为内核边界，把用户程序区域当空闲页分配给了 PD/PT → 代码被覆盖linker_flat.ld 移 .userprogs 到 _kernel_end 之前（最终因 #2 弃用该段，C 数组在 .rodata 内天然受保护）
最终状态：重跑 run → 3 个用户进程在用户态经 0x80 门输出计数（串口 282+ 条 [pidN] + 屏幕底部两行交替刷），全程 0 个 PAGE FAULT；kill / stop / 运行中 ps 全部实测通过。

内存与特权模型

共享页目录（单一 CR3）

所有进程同一 CR3、恒等映射 1MB+。不做独立地址空间，用 PTE 的 USER 位 + 段选择子 RPL 双保险区分用户/内核权限。用户页 flag=0x7（P+W+U），内核页无 U 位 → 用户访问内核页触发 #PF（本次 bug 即此位未写入）。

纯内核栈切换

每个用户进程分配 3 个物理页：内核栈（存上下文帧 regs_t）+ 用户代码页 + 用户栈页。切换 = 保存当前帧指针 → 换 TSS.esp0 → sched_do_switch 换 esp → iret。无 TSS 硬件任务切换，无浮点上下文（用户程序禁用 SSE/x87）。
