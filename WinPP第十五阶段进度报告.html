一句话总结

S11-S14 让内核"学会收发电报（网络）"，S15 让内核"自己开店当服务器"：HTTP 服务器（Windows 浏览器直接打开内核的网页）＋ 跨机聊天服务（Windows 的终端连上来发消息，内核收到并原样回显）。到这一步，你的内核已经是一个能对外提供服务的"迷你网络主机"。

本阶段完成内容

#模块类型说明
1src/httpd.h + httpd.c新增HTTP 服务器（8080）+ 跨机 TCP 聊天服务（7784）：httpd_start/chat_start 绑定监听；httpd_poll/chat_poll 周期处理。HTTP 只支持 GET，解析请求头边界 \r\n\r\n 与请求行取路径，返回 / 主页（内建 HTML，带 uptime/内存/TCP 收发实时值）、/info 纯文本、其余 404。chat 收到数据打印屏幕+串口并原样回显。内核无 snprintf，全部手写 k_utoa/k_cat 拼装。
2src/shell.c修改新增 cmd_httpd / cmd_chat 两条命令 + 命令表条目 + help 文案（"HTTP server on :8080 (browser: 127.0.0.1:8080)" / "TCP chat server on :7784 (echo to client)"）。
3src/kernel.c修改IRQ0 定时器中断里，每 10 tick（约 100ms）调 tcp_poll() + httpd_poll() + chat_poll()，让服务器在后台自动收发处理。
4slirp.conf修改新增 tcp::8080、tcp::7784 两条 hostfwd（Windows 127.0.0.1 端口 → 内核）。因 Bochs slirp 的 hostfwd 规则有上限，注释了 S14 演示端口 7781/7782，当前保留 5 条。
5构建产物更新kernel.bin 289 sectors（约 147 KB），floppy.img 可启动软盘镜像，构建 0 error 0 warning。

Bug 修复记录

#问题修复实测结果
1Bochs slirp 报 "too many 'hostfwd' rules"——hostfwd 规则数超 Bochs 上限（7 条），新增的 8080/7784 端口全部不生效，Windows 连接被拒绝（10061）精简 slirp.conf：注释 S14 演示端口 7781/7782，保留 5 条核心映射（udp 7777/7778、tcp 7779/8080/7784）8080、7784 全部连通 ✓
2HTTP 第一个请求成功，但 /info、/nope 全部超时——TCP 连接被对端 FIN 后进入 CLOSE_WAIT→LAST_ACK，连接槽（TCP_MAX=2）未释放，后续 SYN 到达时找不到 LISTEN 槽被丢弃httpd_poll/chat_poll 开头增加"连接结束（非 LISTEN/ESTABLISHED）→ used=0 → 重新监听"逻辑连续 6 次请求全部 200/200/404，日志见 conn done -> re-listen ✓

当前能力与已知限制（诚实说明）

项说明
TCP 连接表仅 2 条httpd 与 chat 各占 1 条，同一时间只能服务 1 个 HTTP 客户端 + 1 个聊天客户端；连接结束后自动回收（100ms 内检测，3 秒兜底）。
HTTP 响应 ≤ 512 字节教学内核发送缓冲限制，主页 453B / info 237B / 404 175B 均在范围内。
HTTP 仅支持 GET不支持 POST/表单提交；只解析请求行和头部边界，够演示用。
slirp hostfwd 上限Bochs 的 slirp 转发规则约 5 条上限，演示端口需取舍（真机无此限制）。当前 5 条：udp 7777/7778、tcp 7779/8080/7784。
局域网真机本阶段在 Bochs 内通过 slirp 转发完成跨机验证；真机 NIC 直连物理网络（真机里程碑 S20）时不受 hostfwd 限制。

下一阶段预告：S16 硬盘驱动（ATA PIO）

S15 之后，内核已经"能上网、能当服务器"。下一步 S16 是硬盘驱动：让内核认识真正的硬盘（ATA PIO 读写磁盘扇区），为 S17 的磁盘文件系统（把文件真正存进硬盘、断电不丢）打地基。S1-S15 的文件系统是内存模拟的，S16/S17 之后才有"真硬盘上的持久化文件"。

路线图节点：S14 socket+DNS → S15 网络服务 ✓（本次） → S16 硬盘驱动 → S17 磁盘文件系统 → S18 用户态库 → S19 POSIX 完善 → S20 真机里程碑。
