# WinPP 主机通讯说明（Windows ⇄ 内核，S11）

> 一句话：**外面的 Windows 现在能跟内核双向通讯了** —— 发消息、收消息，还能远程执行内核命令并把内核屏幕回传到 Windows。

## 1. 链路长什么样

```
                          Bochs 2.8
   ┌──────────────┐   slirp 用户态网络（10.0.2.0/24）   ┌──────────────────┐
   │  Windows 宿主 │                                    │  WinPP 内核       │
   │              │  UDP 127.0.0.1:7777 ──hostfwd──▶     │  10.0.2.15:7777  │ chatd 7777 echo
   │ winpp-host.py│  UDP 127.0.0.1:7778 ──hostfwd──▶     │  10.0.2.15:7778  │ chatd 7778 cmd
   │  监听 :40001 │  ◀── slirp NAT ── 10.0.2.2:40001 ◀── │  host <text>     │
   └──────────────┘                                    └──────────────────┘
```

- 内核地址 **10.0.2.15**，网关/宿主 **10.0.2.2**（slirp 默认网段），网卡 NE2000（IO 0x240 / IRQ 10 / MAC 52:54:00:12:34:56）。
- 宿主 → 内核：靠 `slirp.conf` 里的 `hostfwd`；内核 → 宿主：内核往 `10.0.2.2:<宿主端口>` 发包，slirp 直接送到宿主。

## 2. 两步跑起来

**① 启动内核**（双击或命令行）

```
D:\WinPP\启动WinPP内核.bat
```

**② 在 Windows 上开通讯台**（双击）

```
D:\WinPP\启动主机通讯台.bat
```

**通讯端点开机就自动绑好了**（串口会打印 `[net] comms endpoints: :7777 echo, :7778 cmd`），
所以不用在内核里敲任何命令就能直接通讯：

- 在通讯台里敲一行 → 内核收到（内核里用 `chatd` 查看）；内核回 ACK 也实时显示；
- 通讯台里 `/cmd netstat` → 内核真的执行 `netstat`，并把**内核屏幕**回传到 Windows；
- 内核里 `host <文字>` → 通讯台立刻显示内核发来的消息。

> 想手动控制端点也可以（会覆盖默认绑定）：`chatd 7778 cmd` / `chatd 7777 echo`。

命令行（脚本化）也可以：

```powershell
python D:\WinPP\winpp-os\winpp-host.py --send "hello"          # 发消息并等 ACK
python D:\WinPP\winpp-os\winpp-host.py --cmd "netstat"         # 远程执行内核命令
python D:\WinPP\winpp-os\winpp-host.py --monitor               # 只听内核发来的
```

## 3. 内核侧命令一览（新增/改动）

| 命令 | 作用 |
|---|---|
| `ip [a.b.c.d]` | 看/改本机 IP（默认 10.0.2.15；改完会重新 ARP 公告） |
| `gw [a.b.c.d]` | 看/改网关（= 宿主侧，默认 10.0.2.2） |
| `ping <ip>` | 发 ICMP 并**真等 1 秒**看回包（`ping 10.0.2.2` 能通） |
| `host <文字>` | 主动发一条 UDP 给宿主通讯台（10.0.2.2:40001） |
| `hostport [n]` | 看/改宿主通讯台端口（默认 40001） |
| `chatd <port> [echo\|cmd]` | 绑定端点：`echo` = 收到即回 ACK；`cmd` = 当命令执行 + 回传屏幕 |
| `chatd` | 查看**所有端点**上收到的消息（多端点都列） |
| `netstat` | 地址/网关/ARP（含 req/rep/pending）/ICMP/UDP 计数与端点 |

## 4. 这次修掉的三个真问题（都是"通讯不通"的直接原因）

1. **网卡 16 位字模式（致命）**：`NE2K_DCR_BYTE` 旧值是 `0x0D`，其中 **bit0(WTS)=1 表示 16 位字传输**，而驱动是按字节读写数据口的 —— 结果每个字节都被网卡发成「xx 00」，ARP 帧在 slirp 里整帧翻倍（`ff 00 ff 00 ...`），收发全花、ARP 永远解析不出来，`ping` 自然超时。
   修复：DCR 改成 `0x00`（8 位字节模式、LAS=0、非环回）。修复后 slirp 抓包里 ARP 干净，并且**slirp 正常回了 ARP 应答**（旧注释里"slirp 不回 ARP"是被这个故障误导的结论）。
2. **内核 IP 不在 slirp 网段**：原来是 `192.168.0.10/网关 192.168.0.1`，而 slirp 网段是 `10.0.2.0/24`（网关 10.0.2.2）—— 网段不对，slirp 既不回 ARP 也不转发。修复：默认 `10.0.2.15` / `10.0.2.2`，并加了 `ip`/`gw` 运行时可改。
3. **`slirp.conf` 端口转发没生效**：`hostfwd` 那行被上一行的中文注释"吃掉换行"合并成了注释；另外第一行必须严格是 `# slirp config`（Bochs 用它校验，多写括号内容有整份配置被忽略的风险）。修复：文件改成纯 ASCII、首行严格、`hostfwd` 独立成行（7777 与 7778 各一条）。

顺带把 ARP 做成规范实现：**无 ARP 条目时先暂存这一帧 + 发 ARP 请求，回复到了自动补发**（不再"往广播 MAC 硬发"），并让内核上线时先做一次 ARP 公告，宿主方向第一包就不会丢。

## 5. 排障清单

| 现象 | 检查 |
|---|---|
| `ping 10.0.2.2` 超时 | `netstat` 看 `arp_rep`；若为 0，先确认 bochsrc 里 `ne2k:` 行用的是本目录的 `slirp.conf`，且内核 IP 是 10.0.2.15 |
| 通讯台收不到内核消息 | `netstat -ano -p UDP \| findstr 40001`：**是不是有旧的 python 还占着端口**（本工具已改独占绑定，会直接报错提醒） |
| Windows 发不进去 | 内核里先 `chatd 7778 cmd` / `chatd 7777 echo`；确认 `slirp.conf` 里 7777/7778 两条 `hostfwd` |
| 想换端口 | 内核 `hostport <n>` / `chatd <port> ...`；宿主 `--host-port/--guest-port/--cmd-port`；`slirp.conf` 里加对应 `hostfwd` |
