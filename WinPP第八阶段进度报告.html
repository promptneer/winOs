一句话意义：这台系统第一次有了"主人"和"客人"——root 是管理员（uid=0，想干什么干什么），guest 是普通用户；每个文件/目录都标了谁拥有它、谁能读、谁能写。guest 想读 root 的私密文件？被拒绝（EACCES）。全部 Bochs 实机 + 串口 + 截图验证通过。

S8-1 用户与身份

用户表 + UID + 提示符

user.c 维护账户表：root(uid=0) 管理员、guest(uid=1) 普通用户。shell 当前身份用 user_current_uid()，提示符显示 用户名 + #(root)/$(普通)。
  • login <user> 切换身份、whoami、id
  • 每个进程携带 uid（创建时继承）
  • syscall 15 getuid()：进程查自己身份
实测通过 · root/guest 切换正常
S8-2 文件权限 rwx

owner + mode + 检查

每个文件/目录记 属主 UID 和 mode（owner rwx + other rwx 六位）。读写、建目录、进目录都先查权限；uid=0 恒放行。
  • 预置：/secret.txt 0600（仅 root）、/public.txt 0644（人人可读）、/rootonly 0700（仅 root 可进）
  • 创建者即属主，新文件默认 0644
  • syscall 16 chmod() 动态改权限
实测通过 · 拒绝/放行闭环
S8-3 权限演示进程

user11 权限闭环

user11 用 getuid 报身份，然后实测三件事：读公开文件（应 OK）、读私有文件（root OK / guest 拒）、写自己的文件（OK）。
  • 同一份代码，root 与 guest 各跑一轮对比
  • 串口铁证：sec-read-OK vs sec-read-DENIED
  • chmod 644→guest 可读；chmod 600→guest 被拒（实时生效）
实测通过 · 权限闭环完整

设计修正

修正 1：chmod 模式用十进制解析，与 Linux 八进制语义不符

最初 k_atoi("644")=644 十进制，与 Linux 的 chmod 644（八进制）含义完全不同。修正：新增 k_octal 八进制解析，"644" → 0o644。

修正 2（测试工具）：注入脚本缺 '/' '.' 键映射

Bochs 注入脚本字符表没有 / 和 .，导致 /secret.txt 实际敲成 secrettxt。修正：_sendkeys.py 补 VK 0xBF(/) 与 0xBE(.) 映射。
