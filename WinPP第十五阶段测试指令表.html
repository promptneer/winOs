阶段主题：网络服务 —— 跨机 TCP 聊天服务 + 简单 HTTP 服务器 ｜ 逐项实测勾选，全部通过后才能进入 S16

本阶段是什么（一句话）

S15 让你的内核变成"能上网提供服务"的机器：跑一个 HTTP 服务器（用 Windows 浏览器直接打开内核页面），跑一个跨机聊天服务（Windows 的终端/程序连上来发消息，内核收到并回显）。第三阶段是"多个程序能同时跑"，第四阶段是"每个程序有自己的天地"，S11-S14 是"学会发消息"，S15 是"内核自己开店当服务器"。

测试方法（先读这一段）

第 1 步：双击 D:\WinPP\启动WinPP内核.bat 启动内核（等约 5 秒出现 WinPP shell）。

第 2 步：在 WinPP shell 里输入下面的命令，回车执行。带 Windows 端标记的项需要在 Windows 的浏览器或终端里操作。

第 3 步：每测完一项，点该项右侧的 ☐ 勾选框打勾。勾选会保存在本机浏览器（localStorage），下次打开还是保留状态。

提示：如果看不到"正常显示"里的内容，先确认命令拼写；重启内核后需要重新输入 httpd 和 chat 两条启动命令（它们不是开机自启的）。

失败排查速查

现象原因与处理
httpd 回车后没有 [httpd] listening :8080TCP 连接槽被占满（本阶段内核 TCP 连接表只有 2 条，httpd/chat 各占 1 条）。先按 tcpstat 看状态，若显示 CLOSE_WAIT/LAST_ACK，等 3 秒会自动释放并重新监听；或重启内核。
Windows 浏览器打不开 http://127.0.0.1:8080/确认内核里已执行 httpd；确认 Bochs 已启动（slirp 才转发端口）；若提示"连接被拒绝"，等 2 秒重试一次（连接槽释放中）。
/info 或 /nope 卡住超时这是"连接结束后槽未释放"的老 bug，S15 已修复：连接关闭后会自动 re-listen。仍出现就重启内核再测。
chat 回车后 Windows 连 7784 没反应确认 chat 已执行且显示 [chat] listening :7784；用 tcpstat 看连接状态；Windows 端连 127.0.0.1:7784（不是别的端口）。
发消息后内核屏幕没显示 [chat] rx确认发送端发送的是纯文本（如 hello）并回车/发送；消息长度不超过 512 字节。
